# Ступень 3. OpenSpec, код и проверка результата

Результат упражнения — проверенная связь между требованиями, кодом и тестами, с явно названными пробелами. В репозитории одна реализация калькулятора. ИИ-дополнение работает с ней же.

## Начать

Нужны Git, Node.js 22+ и npm. Клонируйте репозиторий, создайте свою ветку и установите зависимости:

В командах замените `your_login` на свой GitHub-логин. Для повторного прохождения добавьте к имени ветки суффикс `-2` и используйте его также в push. Учебные результаты не сливают в общую `main`, чтобы сохранить исходный эталон.

```bash
git clone https://github.com/apolenkov/sdd-guide-credit-calculator-stage-3.git
cd sdd-credit-calculator-example
git switch -c feature/your_login/stage-3-review
npm ci
npm run check
```

Работайте из корня. OpenSpec устанавливается локально вместе с зависимостями; Store на этой ступени не требуется. Для отправки учебной ветки нужен доступ на запись от организатора обучения.

## Разберите пример

Создайте учебную задачу в Jira, если её ещё нет. Используйте проект DEMO, тип Task и Epic Link / Parent `DEMO-1 · учебный эпик курса` Название: «Проверить связь OpenSpec с реализацией кредитного калькулятора». В описание скопируйте:

```text
Учебная цель: проверить соответствие действующей спецификации кредитного
калькулятора реализации и тестам, не меняя поведение приложения.

Результат: review.md с проверкой каждого сценария, фактическими результатами
и обнаруженными пробелами; ссылка на PR с проверками аналитика и разработчика.
```

Если родитель недоступен, уточните у организатора обучения актуальный учебный эпик. Не создавайте новый эпик самостоятельно.

1. Прочитайте действующую спецификацию в openspec/specs/credit-calculator/spec.md.
2. В openspec/changes/archive/2026-08-31-add-credit-calculator прочитайте proposal.md, specs/credit-calculator/spec.md, design.md и tasks.md. Это история готового изменения, а не задание, которое надо выполнить заново.
3. Сопоставьте каждый сценарий действующей спецификации с src/calculator.ts, src/app.ts и test/calculator.test.ts.
4. Создайте review.md с таблицей: сценарий → место реализации → тест или ручная проверка → фактический результат → пробел. Отсутствующий тест отмечайте как пробел, даже если функция выглядит правильной.

## Проверьте в браузере

В отдельном терминале корня запустите:

```bash
npm run dev
```

Откройте http://127.0.0.1:4173/ и проверьте:

| Ввод | Ожидание |
| --- | --- |
| 3 000 000 ₽, 16%, 240 месяцев | 41 738 ₽ |
| 120 000 ₽, 0%, 12 месяцев | 10 000 ₽ |
| Сумма 0 | Ошибка суммы, результат «—» |
| Срок 1,5 месяца | Ошибка целого срока, результат «—» |

Для сценария локальной обработки дождитесь загрузки страницы, очистите Network в DevTools, выполните расчёт и проверьте отсутствие запросов, передающих введённые данные. В Application/Storage проверьте Local Storage и Session Storage. Запишите наблюдения в review.md. Проверка исходников сама по себе не доказывает этот сценарий.

Сервер работает до Ctrl+C; его постоянная работа не является зависанием агента. Не поручайте агенту ждать завершения npm run dev, чтобы перейти к следующему шагу.

## Передайте результат на review

Повторите npm run check, прочитайте git diff и сохраните только свой отчёт:

```bash
git add review.md
git commit -m "docs: review spec implementation coverage"
git push -u origin feature/your_login/stage-3-review
```

Откройте PR в main. Другой аналитик проверяет содержание отчёта, затем разработчик или архитектор проверяет доказательства связи с кодом. После нового коммита нужны актуальные подтверждения обоих. В созданной в начале задаче Jira сохраните ссылку на PR и фактические проверки.

После двух подтверждений закройте учебный PR без слияния в общую `main`. Сохраните ветку и отчёт как результат упражнения. Сопровождение исходного эталона выполняется отдельно владельцем репозитория.

## ИИ-дополнение и 3★

Для ИИ-предпроверки используйте [готовое сообщение](ai/request.md) в OpenCode с корпоративным агентом. Результат проверяют те же люди.

Продолжение 3★ находится в [метарепозитории](https://github.com/apolenkov/sdd-guide-credit-calculator-stage-4-requirements). Там готовится новый Change; исходная ступень 3 остаётся самостоятельным примером. Переход рабочего клона к Store должен быть явным, с одним владельцем требований.
