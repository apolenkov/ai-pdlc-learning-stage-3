# Правила факультативной ступени R3

- Полный маршрут курса: Введение → R1 → R2 → обязательные SDD и OpenSpec → R4. Этот репозиторий — факультативная практика ручного планирования; он не заменяет SDD или R4.
- Для самостоятельного входа создайте личную `course/<login>/stage-3-base`, затем рабочую `course/<login>/stage-3-reset-years`. Planning MR направляется в личную base-ветку корпоративного fork, не в общую `main`; сохраняйте правила GitLab и владельца репозитория.
- В R1–R3 используется один запрос и один intent с историей Git. Для позднего старта сформируйте intent по `request-and-answers.md` и `intent-template.md` до переноса требований; не создавайте отдельный intent для каждого урока.
- Для текущего diff курса нужны отметки руководителя проекта, аналитика и технического руководителя; при затрагивании архитектуры или споре добавляется отметка архитектора. Автоматическая проверка и ИИ не заменяют людей.
- OpenSpec здесь repo-local: действующие требования находятся в `openspec/specs`, история — в `openspec/changes/archive`, согласованное не реализованное поведение — в активных Changes.
- На ручной R3 создаётся или продолжается `add-reset-and-years-term` через native `status` и `instructions`. Можно работать без модели. Apply, правки приложения/runtime-тестов, закрытие tasks и архивирование Change запрещены.
- Исходное состояние — только поведение существующего приложения, подтверждённое кодом и проверками. Отсутствующее поведение не превращайте в main spec или факт реализации.
- Перед коммитом проверяйте актуальный diff и состав staged-файлов. SHA фиксируйте для происхождения, передачи или по требованию; не заменяйте недоступный источник текущей `main`.
- `npm run check` проверяет существующее состояние, но не будущие функции и не заменяет человеческие отметки.
- В R4 передаются все активные Changes и фактический набор main specs, даже если он пуст. SHA планирования и service pin — независимые доказательства разных ролей.
- Store используется только в личном product-meta. `.workspace` всегда read-only; реализация выполняется в отдельном checkout сервиса после отдельного разрешения.
- Не менять Store-регистрацию, не применять force и не сбрасывать чужие изменения автоматически. При неверной папке, ветке, root, SHA или грязном дереве остановиться с точной причиной.
- Не сохранять секреты, персональные данные, рабочие корпоративные документы и выдуманные Jira-ссылки.
