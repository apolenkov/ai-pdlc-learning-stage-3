# Правила ступени 3

- Учебную работу ведите в персональной ветке. Не отправляйте её напрямую и не сливайте в общую main эталона; после review сохраните ветку и закройте учебный PR без слияния. Сопровождение эталона владельцем — отдельная задача.

- Действующие требования находятся в openspec/specs; история — в openspec/changes/archive. Согласованный, но не реализованный Change остаётся активным в openspec/changes.
- Это repo-local OpenSpec: команды из корня не требуют регистрации Store.
- Код находится в src, тесты — в test. ИИ использует эти же файлы.
- Начните с README, provenance переноса и относящейся к заданию спецификации. Не добавляйте функции ради прохождения проверки.
- Для изменения поведения используйте стандартный OpenSpec Change и человеческое review перед реализацией.
- Проверяйте npm run check. Результаты ручной проверки не придумывайте.
- Не запускайте долгоживущий dev-сервер как блокирующий шаг выполнения задания.
- Не сохраняйте секреты, персональные данные и рабочие корпоративные документы.

## Граница учебного задания

- На ступени 3 готовится Change `add-reset-and-years-term`; Apply не запускается, код калькулятора и runtime-тесты не меняются.
- Baseline содержит только подтверждённое текущее поведение. Ещё не реализованные reset в обоих режимах и переключатель срока «месяцы / годы» должны оставаться в активном Change с отдельными незавершёнными задачами и проверками.
- Личный Markdown ступени 2 переносится по полному SHA. Не подменяйте его общей main или эталоном. Удалять рабочий `specification.md` можно только после полного сопоставления требований и сценариев.
- ИИ и автоматические проверки не заменяют два последовательных человеческих review актуального diff.
- В персональном Store-only продолжении используйте явный `--store sdd-credit-calculator-product-meta`, сначала проверьте root и сохранность baseline вместе со всем активным Change. Не поддерживайте локальную и Store-копии как два редактируемых контракта.
