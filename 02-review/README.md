# Ступень 2 — два последовательных ревью

**Ветка:** базовая. Она наследует базовую ступень 1 и не требует прохождения `1-ИИ`.

Сначала выполните корневой быстрый старт. Все npm-команды запускайте из корня репозитория.

OpenSpec CLI на этой ступени ещё не используется. Работа идёт с [`specification.md`](specification.md) через [шаблон запроса на слияние](../.github/pull_request_template.md).

## Порядок

1. Автор обновляет спецификацию и из корня запускает `npm run validate:structure` и `npm run validate:links`.
2. Другой аналитик выполняет ревью аналитика и фиксирует решение в [`review/01-analyst-review.md`](review/01-analyst-review.md).
3. Только после принятия содержания разработчик или архитектор выполняет техническое ревью и фиксирует решение в [`review/02-technical-review.md`](review/02-technical-review.md).
4. Автор закрывает замечания и добавляет оба решения в Pull Request.
5. Ссылка на принятый Pull Request добавляется в Jira.

CI запускает `npm run check` для каждого запроса на слияние. Зелёный CI подтверждает структуру, ссылки, тесты, приватность и сборку, но не заменяет два человеческих решения.

## Что считается ревью

Каждое ревью выполняет отдельный человек. В записи нужны роль проверяющего, дата, статус, замечания и доказательство их закрытия. Галочки автора или пустая форма не считаются ревью.

## Результат

К базовой ступени 1 добавлены два решения разных ролей в заданном порядке: сначала по содержанию, затем по реализуемости.
