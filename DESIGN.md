# Устройство ступени 3

Репозиторий совмещает готовую TypeScript/Vite-реализацию калькулятора и самостоятельный repo-local OpenSpec. Код находится в `src`, тесты — в `test`, действующий baseline — в `openspec/specs`, планы — в `openspec/changes`.

Учебная работа не меняет приложение. Личная Markdown-spec ступени 2 используется как временный вход для построения прослеживаемости:

```text
личный SHA R2
  └─ specification.md
       ├─ подтверждённое текущее поведение → baseline
       └─ не реализованные reset + режимы срока → активный Change
             └─ сценарий → незавершённая task → проверка результата
```

После полной сверки рабочая копия `specification.md` удаляется, но остаётся в import-коммите и исходном репозитории. Change `add-reset-and-years-term` остаётся активным после review: согласованный план не равен реализации.

Текущий ввод целого срока в месяцах сохраняется. Планируемый переключатель «месяцы / годы» выбирает единицу ввода и сам не запускает расчёт. Режим лет использует шаг `0,5`, default `20 лет`, переводит годы в целые месяцы и сохраняет эквивалентность `0,5 года = 6 месяцев`, `20 лет = 240 месяцев`. Reset работает в обоих режимах, сохраняет выбранный режим, возвращает `3 000 000 ₽`, `16%` и срок `240 месяцев` либо `20 лет`, очищает ошибки и результаты и не пересчитывает автоматически.

Общая `main` остаётся repo-local. В необязательном продолжении отдельная персональная ветка переходит к Store-only только после переноса baseline и всего активного Change. `.workspace` product-meta используется только для чтения; реализация выполняется в отдельном checkout сервиса.

`npm run check` проверяет типы, существующие тесты, ссылки, приватность, OpenSpec и сборку. Эта команда не доказывает reset в обоих режимах, переключатель срока или диапазон суммы до их отдельной реализации и проверки.
